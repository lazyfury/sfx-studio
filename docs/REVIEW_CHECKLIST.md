# 审查清单（Rust / 音频 / 导出）

每次审查按此表逐项检查。每项标记 `OK / N/A / Blocker / Major / Minor`，Blocker 必须修复。

## 1. 正确性

- [ ] 索引访问都有边界保护；加载的数据不会导致 panic。
- [ ] `f32` 的 NaN / Inf 在加载、DSP、导出路径上都有防御。
- [ ] 时长、采样率、频率、增益在 UI 范围与加载校验之间一致。
- [ ] 播放 / 暂停 / seek / 循环 / 自然结束的状态转移自洽。
- [ ] Undo/Redo：无空快照、无重复快照、跨工程不串历史、选中项被 clamp。
- [ ] 打开/保存失败时不会静默覆盖或清空当前工程。

## 2. 数据安全与格式

- [ ] 保存是「临时文件 + rename」，失败不破坏旧文件。
- [ ] 工程有 `version`，新增字段有 `serde(default)`，需要时提供迁移。
- [ ] 加载后执行 `validate()`：clamp、去重名、数组上限、非法值修复。
- [ ] 导出文件名唯一；中文/重名/空名不会互相覆盖。
- [ ] `.tres` / manifest 的字段变化有往返测试（写 → 读 → 再写）。
- [ ] 文档（`docs/FORMAT.md`）与实现一致。

## 3. 音频实时性

- [ ] 音频回调内不分配、不打日志、不做文件 I/O。
- [ ] 回调不长时间持锁；播放状态用原子变量。
- [ ] 循环回绕、停止、seek 不产生爆音（有 fade）。
- [ ] 渲染不在 UI 线程长时间阻塞；拖动有节流或后台化计划。
- [ ] 采样率变化（设备率 / 导出 48k / bake rate）不会让音色意外改变，或已文档化。

## 4. DSP 与跨端一致性

- [ ] 改公式时同步 `dsp_version` / `docs/PARITY.md`。
- [ ] RNG、精度、相位回绕、包络公式与 Godot 的差异已记录。
- [ ] 新波形/参数同时补 Rust 与 Godot（或明确只在一端支持）。
- [ ] `tone_env/exp_decay`、`normalize`、`_s16` 等易漂移点有对照测试。
- [ ] 渲染结果有限、峰值合理、长度符合预期。

## 5. UI / 交互

- [ ] 布局几何只有一个来源（`ui::Layout` / metrics helpers）。
- [ ] 1024px 宽窗口下无重叠、无越界按钮。
- [ ] 命中测试与绘制使用同一份布局；滚动容量一致。
- [ ] 中文显示名不被 sanitize 破坏；导出才做文件名转换。
- [ ] 提示文案与实际控件一致（如 Cutoff 轨道不写 GAIN）。
- [ ] 模态框：Enter/Esc 行为正确，确认操作不会误触发。

## 6. 性能

- [ ] 每帧不做 O(样本数) 的全量扫描（peak / 波形应缓存）。
- [ ] 拖动参数不会每帧重渲染整段音乐/音效。
- [ ] 大数组有上限；渲染 buffer 有防御性上限。
- [ ] 没有为小改动引入不必要的 clone（或已说明原因）。

## 7. 测试

- [ ] 修复的 bug 有回归测试（优先纯函数级）。
- [ ] 新格式/新导出有端到端临时目录测试。
- [ ] 布局/命中改动有布局测试。
- [ ] 测试不依赖真实音频设备、网络、用户目录。
- [ ] `cargo test` 无 ignored 的临时测试残留。

## 8. 工程与流程

- [ ] `cargo fmt --check` 通过。
- [ ] `cargo clippy --all-targets -- -D warnings` 通过。
- [ ] `cargo run -- --selfcheck` 通过。
- [ ] `docs/PLAN.md` 状态更新。
- [ ] `docs/reviews/NNNN-*.md` 有独立第二审查与 `source_hash`。
- [ ] 没有 `_keep`、注释掉的代码、无理由的 `#[allow]`。
- [ ] 新增依赖有理由、许可可接受、版本可复现。

## 9. 发布前（导出/插件）

- [ ] `--bake`、`--export`、`--dump` 在临时工程上成功。
- [ ] Godot 侧 `self_test.tscn` 通过（涉及 `.tres`/插件时）。
- [ ] manifest 版本、字段与消费方兼容。
- [ ] 备份/回滚方式明确（旧 WAV、旧 `.tres` 如何保留）。
